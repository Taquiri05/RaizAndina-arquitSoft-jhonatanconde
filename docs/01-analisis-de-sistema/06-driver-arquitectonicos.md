# Drivers arquitectónicos

| ID | Driver arquitectónico | Origen | ¿Por qué influye en la arquitectura? | ADR relacionado |
|---|---|---|---|---|
| DA01 | El sistema debe soportar entre 500 y 1 000 usuarios conectados a la vez entre las 3 sedes, con picos en horas punta. | AC01, AC02 – Rendimiento y Escalabilidad | Obliga a usar caché de la carta, cola de pedidos por sede y un backend sin estado (stateless) que pueda escalar horizontalmente. | ADR-001, ADR-003 |
| DA02 | El estado de un pedido debe reflejarse en el cliente y en cocina en tiempo real, en pocos segundos. | AC03 – Tiempo real | Obliga a usar WebSockets (Socket.IO) con salas separadas por sede y por pedido, coordinadas mediante Redis cuando hay varias réplicas. | ADR-008 |
| DA03 | Los pagos se confirman de forma asíncrona mediante webhooks de una pasarela externa (Mercado Pago), que pueden fallar o llegar duplicados. | RC05 – Pagos, AC06 – Integridad | Obliga a verificar cada webhook, a que la confirmación del pago sea idempotente, y a una tarea de conciliación periódica como respaldo. | ADR-004, ADR-006 |
| DA04 | Cada sede debe ver y modificar solo sus propios datos (menú, pedidos, inventario, reservas). | AC05 – Seguridad | Obliga a un control de acceso (RBAC) con rol y sede incluidos en el token de sesión, aplicado siempre en el backend. | ADR-005 |
| DA05 | El sistema debe poder crecer desde un conjunto inicial de módulos hasta 9 módulos sin reescribirse, manteniendo un único frontend. | AC07 – Modificabilidad | Obliga a un monolito modular con módulos de fronteras y dependencias explícitas, en vez de microservicios, y a una sola aplicación web con una experiencia por rol. | ADR-001, ADR-010 |
| DA06 | Cambiar un proveedor externo (por ejemplo la pasarela de pago) o una regla de un módulo no debe afectar innecesariamente a los demás módulos. | AC07 – Modificabilidad | Influye en la separación de responsabilidades, el uso de adaptadores para servicios externos y las dependencias internas entre módulos. | ADR-002, ADR-004 |
| DA07 | La interfaz web y los sistemas externos se comunican con el backend mediante una API REST en formato JSON, y el tiempo real se atiende por un canal aparte (Socket.IO). | RC07 – Aplicación web, RC09 – API REST | Obliga a definir contratos de API claros por recurso (sedes, productos, pedidos, pagos), con control de acceso en cada ruta y un formato de error uniforme. | ADR-011 |
